# TradeFlow Lite 行情数据源适配器接入指南（v3）

本文是 TradeFlow Lite 当前 v3 编译期行情适配器合同。它面向需要把自己购买的行情 API 接入 Lite 的开发者，也可作为 AI 按 API 文档生成适配器时的约束。当前版本不提供运行时插件加载，不执行用户提供的脚本，也不接受不安全的动态库 ABI。

## 1. v3 的边界

统一合同覆盖历史 K 线、报价、目录和推送实时四个独立 facet。历史返回 `HistoryResponse`，独立报价返回带有 `provider_id`、`symbol`、`source` 和 `quote` 的 `QuoteResponse`；一次请求在同一个 Rust 调用中完成校验并返回，不经过 JSON。

四项能力独立声明在 `ProviderCapabilities` 中：

| 能力 | 含义 | v3 调用边界 |
| --- | --- | --- |
| `history` | 能按 `HistoryRequest` 返回完整历史 K 线 | `MarketDataAdapter::fetch_history` |
| `quote` | 能提供独立的严格报价快照，并可为历史响应附带报价 | `QuoteAdapter::fetch_quote`；历史 `quote=None` 允许降级 |
| `catalog` | 能提供动态品种目录 | `CatalogAdapter::list_symbols`，返回稳定的 `CatalogSymbol` |
| `realtime` | 能提供推送式实时流 | `RealtimeAdapter::replace_subscription`，通过 typed `RealtimeSink` 输出统一 envelope |

TDX 的内置证券目录是 `market-universe.json` 静态快照，不属于 provider 的动态 `catalog` 能力；TDX 当前实时更新是既有历史/报价轮询，不属于推送式 `realtime` 能力。它的历史和报价仍通过统一适配器合同。Binance Spot 与 USD-M 的四项能力在启用 `provider-binance` feature 时全部声明，并由各自的历史、报价、目录和实时 facet 实际承接调用。应用通过 provider-neutral 的 `list_market_providers` 与 `list_market_catalog(providerId, venue)` 发现目录，旧 Binance 命令仅是兼容外壳。

目录和实时请求都在操作开始时通过 `AdapterRegistry` 解析一次。目录命令保留现有 Tauri 命令名和前端字段，但实际调用 `CatalogAdapter`；实时线程由 provider facet 启动并把 `requestId`、`providerId`、`symbol`、`resolution` 和 `sequence` 放进统一 envelope，再由 Tauri `RealtimeSink` 发给前端。实时热路径不逐事件查表、不把事件往返 JSON；旧 Binance aggTrade + kline 校准、depth、重连退避和活动 request id 语义保持在 Binance facet 内。

## 2. 稳定合同

公共类型位于 `src-tauri/src/market_adapter.rs`，可由编译进 Lite 的适配器实现：

`ProviderDescriptor.id` 是稳定的 provider identity，同时会进入前端的
`providerId|symbol` 持久化 key。它必须是 1 至 64 个 ASCII 字符，且只能包含英文字母、
数字、`.`、`_`、`-`；不得包含 `|`、空白、控制字符或 Unicode 字符。Registry 注册时会拒绝
不符合规则的 id，前端和 Rust 使用同一语法，避免不同 provider 的本地状态串线。

```rust
use tradeflow_lite_lib::contracts::{Adjustment, AppError, Bar, Resolution, Symbol, SymbolKind};
use tradeflow_lite_lib::market_adapter::{
    AdapterRegistration, HistoryRequest, HistoryResponse, MarketDataAdapter,
    ProviderCapabilities, ProviderDescriptor,
};

static MY_DESCRIPTOR: ProviderDescriptor = ProviderDescriptor {
    id: "example.provider",
    display_name: "Example Provider",
    version: "1",
    contract_version: "3",
    enabled: true,
    capabilities: ProviderCapabilities {
        catalog: false,
        history: true,
        quote: false,
        realtime: false,
        venues: &["EXAMPLE"],
        kinds: &[SymbolKind::Stock],
        resolutions: &[Resolution::Day],
        adjustments: &[Adjustment::None],
    },
};

struct MyAdapter;
static MY_ADAPTER: MyAdapter = MyAdapter;

impl MarketDataAdapter for MyAdapter {
    fn descriptor(&self) -> &'static ProviderDescriptor {
        &MY_DESCRIPTOR
    }

    fn fetch_history(&self, request: HistoryRequest) -> Result<HistoryResponse, AppError> {
        // 直接把供应商响应映射为 Bar；不要先构造 JSON 再解析回来。
        let bars = vec![Bar::new(
            /* 结束时间（Unix 秒） */ 1_757_257_200,
            10.0,
            10.8,
            9.9,
            10.5,
            1_200.0,
            None,
        )];
        Ok(HistoryResponse {
            symbol: request.symbol,
            bars,
            diagnostics: tradeflow_lite_lib::market_adapter::HistoryDiagnostics {
                source: "example.provider",
                host: "api.example.test".to_string(),
                latency_ms: 0.0,
            },
            quote: None,
        })
    }
}

// 注册表条目使用静态引用，不在运行时加载任意代码。
const MY_REGISTRATION: AdapterRegistration = AdapterRegistration::new(&MY_ADAPTER);
```

实际接入时由宿主把 `MY_REGISTRATION` 交给公开的 `MarketRouter::new`（或将 `builtin_registry()` 扩展后用 `MarketRouter::from_registry`），再通过 `run_with_router` 注入 Tauri 入口；默认 `run()` 只构造内置 provider。不要修改 Lite 内部的 `REGISTERED_ADAPTERS`，也不要修改 TDX 协议层来“兼容”外部 HTTP API。若适配器放在独立 Rust crate，Lite 侧只保留同样的薄转换层。Registry 构造时会拒绝重复 provider id、重叠的市场/品种路由和 capability/facet 不一致。

`MarketDataAdapter` 的方法按值接收 `HistoryRequest`，请求必须带 `provider_id`；路由层只借用请求做一次静态能力检查，随后把请求交给 provider，并在响应边界对最终批次做一次全量 K 线校验。provider 应直接移动最终 `Vec<Bar>` 到 `HistoryResponse`；不要为了适配器边界 clone 整批 K 线。若 provider 需要在实时线程中保护单个事件，可单独做单 bar 校验，但不要在历史 provider 和 router 重复做全量校验。若声明 `quote=true`，必须实现 `QuoteAdapter`；目录和实时同理分别实现对应 facet，不能只把 descriptor 的 bool 改成 `true`。

## 3. 数据语义

适配器返回前必须满足以下合同：

- `Symbol` 是稳定的 `VENUE:CODE` 身份；不得用显示名称代替代码；
- 所有 K 线时间使用 Unix 秒，且沿用 Lite 的“结束时间”语义；
- K 线按时间升序、时间唯一；
- `high >= max(open, close)`、`low <= min(open, close)`、`high >= low`；
- 价格、成交量和成交额必须是有限数，未复权价格为正，数量不能为负；
- `count`、周期和复权必须按 descriptor 能力处理；不支持时返回明确错误，不偷偷改周期、复权或换成另一个来源；`include_quote=true` 时报价可以暂时为 `None`，但只要返回 `Some` 就必须通过快照校验；独立 `QuoteRequest` 失败则明确返回错误；
- 一次历史响应只能来自一个完整来源。TDX 的分页固定在同一主站，失败时整次换站；适配器不得在客户端把不同来源的半截数据拼起来；
- `quote` 为 `Some` 时必须通过 `QuoteSnapshot` 的有效性检查；报价异常不能让已经验证的历史 K 线变成错误或空数据。

如果供应商时间是毫秒、微秒或本地时区，必须在 provider 转换层明确换算后再构造 `Bar`。不要把供应商原始时间单位传到统一合同中。

## 4. 目录、实时和 stale request

目录统一通过 `list_market_providers` 获取 provider 描述，再用 `list_market_catalog(providerId, venue)` 获取中性的 `CatalogSymbol`（至少含 `providerId`、带 venue 的 `symbol`、`name`、`kind`，资产字段可选）。旧 Binance 命令保留 `baseAsset`、`quoteAsset` 兼容格式，但内部仍委托同一个通用路由。TDX 静态目录不经过该能力，调用会返回明确的 `unsupported_capability`；feature-disabled provider 的四个入口统一返回 `market_data_source_unavailable`，不会落到 TDX。

`start_realtime_market` 从 Tauri State 取得宿主注入的同一个 `MarketRouter`，在创建连接/线程前完成一次注册表选择，然后调用选中 provider 的 `RealtimeAdapter::replace_subscription`。适配器实例是静态长期实例；支持订阅切换的供应商必须保留已建立的 transport，切换时发送供应商自己的 unsubscribe/subscribe，而不是每次重新做 TCP/TLS/WebSocket 握手。不支持复用的协议可以重启任务，但仍必须及时停止旧任务。每个事件都必须携带并由前端同时核对：

```text
requestId + providerId + symbol + resolution + sequence
```

切品种、切周期或停止订阅会产生更大的 `requestId`。旧订阅收到迟到事件时，Rust 的活动编号检查和前端的选择检查都会拒绝它；复用连接时还必须按返回帧的品种和频道过滤切换途中的旧数据。适配器可以缓存 transport 和供应商元数据，但不能用一个脱离 `requestId` 的全局“当前品种”绕过这层隔离。

实时事件的公共 envelope 是 `requestId`、`providerId`、`symbol`、`resolution`、可选 `sequence`；K 线带 `eventTimeMs`/开放字符串 `source`，深度带 `eventTimeMs`/`bids`/`asks`，成交带中性的 `tradeId`、时间、价格、数量及可选 `side`/`flags`。Binance 的 `aggTrade`、`kline` 和 depth update id 只属于 provider 内部映射，不能泄露为公契约字段。

provider 在每个事件上不得重新解析注册表。TDX 当前没有推送 facet；关闭 `provider-binance` feature 时 Binance registration 仍保留自己的 venue 身份，但四项能力和对应 facet 均关闭，不得回退到 TDX。报价命令 `get_quote_snapshot`、历史命令和目录命令也都从同一份 State router 执行，避免入口之间各自持有 provider 选择。

## 5. AI 快照边界（仅预留）

`MarketDataSnapshot<'a>` 是未来只读 AI Tools 的边界。它从已经完成的 `HistoryResponse` 借用 `Symbol`、`Bar` 切片、报价和诊断，不联网、不保存密钥、不自动上传，也不在行情热路径建立。`recent_bars(max_bars)` 只返回借用的最近切片，不复制数据。

本轮不实现 AI 客户端、API Key 存储、工具调用或持续上传行情。未来用户明确发起 AI 请求后，AI 层应在边界外按大小限制复制/序列化需要的数据，并向用户说明发送给哪一个 Provider。

## 6. feature、测试和性能门

默认构建启用 `provider-binance`。关闭该 feature 时，Binance 注册项保留自己的市场身份，但四项能力置为不可用；请求返回 `market_data_source_unavailable`，绝不会误落到 TDX。

新增适配器至少应有：

1. descriptor 能力和稳定身份合同；
2. 不联网的 fake adapter 合同测试；
3. 时间、排序、OHLC、数量和错误映射测试；
4. 若声明 `quote=true`，实际 provider 请求必须断言返回有效 quote；
5. 若声明 `quote/catalog/realtime=true`，必须补相应 callable facet、入口和事件合同，不能只改布尔值；
6. 真实源验收（网络允许时）与现有来源分开记录。
7. 若供应商支持 WebSocket 订阅切换，连续切品种、切周期和现货/合约时必须证明连接被复用、旧帧被隔离，并记录首次连接与复用切换耗时。

当前可执行的门：

```sh
npm run test:adapter
npm run test:contracts
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features
```

`npm run test:adapter` 是结构回归门：检查公开 trait、四项能力、静态注册点、零 JSON 边界和实时循环不逐事件查表。Rust fake adapter 测试证明第三方实现可以在无网络条件下通过公开合同注册并返回响应；纯路由微基准固定执行 10,000 次无副作用解析，并记录 provider 启动次数为 0。`MarketDataSnapshot` 指针断言证明限定快照不复制 K 线。它们是结构/等价回归证据，不替代真实源延迟或开市窗口验收。

真实 provider transport 与 adapter 路由验收必须分开记录：

```sh
# 直接测试 Binance transport crate；不证明请求经过 Lite adapter
npm run test:real-binance-ws
npm run test:real-binance-usdm-ws

# 通过 MarketRouter::builtin -> AdapterRegistry -> provider facet
npm run test:real-adapters

# 只跑 Spot/U 本位的 adapter WebSocket 全链路（Rust sink 证据）
npm run test:real-adapter-ws
```

`test:real-adapters` 包含 TDX 多市场/多周期历史、Binance Spot 与 USD-M 的目录/历史/独立报价；每条响应都记录 provider、source、symbol、行数和单一来源 host，并检查时间升序。历史请求的附带 `quote` 在开盘前允许为 `None`，但只要返回就必须通过严格的 `QuoteSnapshot` 校验；独立报价仍必须是有效快照，或明确返回 `market_data_unavailable`，不会用昨收冒充现价。

`test:real-adapter-ws` 通过 `MarketRouter::start_realtime` 收集 Spot 与 USD-M 的统一 envelope，检查 `requestId`、`providerId`、`symbol`、`resolution`、`sequence` 以及 status/bar/trade/depth 四类事件，并在完成条件后取消订阅、确认 sink 被 worker 释放。它证明 Rust adapter 到 typed sink 的真实链路，不等同于已安装桌面 App 的 Tauri 事件监听、图表渲染或用户视觉验收；这些仍需单独在开发版 App 检查。测试可能受公共网络、交易时段和 Binance 限流影响，均默认 `ignored`，运行时用 `--nocapture` 保留证据日志。
