## 4. 实施原则

1. 优先级固定为：数据正确性 > 图表稳定性 > 切换体验 > 性能 > 视觉。
2. 历史 K 线每次 attempt 固定一台主站；任何分页失败都丢弃整次结果再换站，禁止跨主站拼接。
3. 前端每次切股、切周期和切复权都有请求代次；旧响应只能被丢弃，不能覆盖当前图。
4. 不复权周/月使用已实测的 TDX 原生周期；前复权周/月必须先复权日线再聚合，避免除权周/月内直接调整整根原生 bar。
5. 不加硬盘行情缓存；切换性能只使用当前进程内、短时、容量受限且已经过 Rust 合同校验的数据复用。
6. TF 项目和 UI 目录只读；按行为、测试和合法资产逐项抽取，不复制私有主站、Pro 逻辑或整套 Charting Library 产物。
7. 每个数据步骤至少保留一项成功日志和一项明确失败日志，方便定位主站、品种、周期、请求代次和耗时。

## 5. 风险与验证记录

| 位置/状态 | 可能影响 | 处理责任 | 验证 |
|---|---|---|---|
| 市场目录来源与字段 | 带入 TF 内部字段或遗漏品种 | 生成时只保留代码、名称、交易所、类型和公开搜索别名 | 字段白名单扫描；股票/ETF/指数计数和代表品种检查 |
| 主站部分返回/分页失败 | 缺 K 线或跨站混合 | Rust `hosts::run_with_failover` 固定 host 完成整个 attempt，验证后才返回 | 注入空页、短页、异常；结果必须整次失败并换站 |
| 快速切股/切周期 | 旧响应覆盖当前选择 | 前端请求代次 + Rust 请求标识 | 人为延迟旧请求，最终图、图例和状态必须属于最后选择 |
| 首屏与深历史互相阻塞 | 每次切换都等待 8,000 根，或深历史补齐后图表跳动 | 300 根首屏 + 延迟/左边界触发的整份深历史 + 时间范围恢复 | 首次打开、连续切换、切回缓存组合、向左拖动分别验证 |
| 时间与聚合 | 分钟边界或周/月结束时间错误 | Rust 统一合同和聚合 | TF 样本对拍；跨午休、跨周、跨月、停牌样本 |
| 前复权 | 除权日边界或因子方向错误 | 独立复权模块，不改原始 bars | 有事件/无事件/多事件样本与 TF 对拍 |
| 实时与断线 | 当前 bar 回退、重复或空图 | 仅 `update` 最新 bar；错误保留最后有效图 | 重复时间、迟到报价、断网、恢复、收盘状态 |
| UI 先于功能 | 再次出现假按钮 | UI 合同禁止未实现入口 | 静态合同 + 实际窗口逐项点击 |
