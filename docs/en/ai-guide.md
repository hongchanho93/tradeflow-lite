# AI and MCP guide

## Built-in conversation

Open **AI → Settings** from the right sidebar. Select your provider, model and API key, then save and return to the conversation. Advanced settings contain the protocol and **complete POST request endpoint**, not just a website or base URL. The implemented protocols are Chat Completions, Responses and Anthropic Messages. Use a model and endpoint that actually support the required tool calls; a protocol match does not guarantee every provider feature is compatible.

Changing a provider endpoint or protocol requires appropriate credentials for that destination. An unauthenticated local model must be configured explicitly as not requiring a key. Consumer subscriptions are not automatically API credentials; no built-in subscription-to-API conversion is provided.

On supported macOS/Windows configurations, saved credentials use the OS credential store. Saving or restoring settings does not contact the model. Sending a message or explicitly resuming a failed request can incur your provider's charges. Do not put keys in prompts, source files or issue reports.

Try a small request first: “Read this chart's actual symbol, timeframe and available data range.” Check that tools really execute. Text that looks like a tool call is not execution evidence.

## Connect an external MCP client

In **AI → Settings → Connect external AI (MCP)**, enable the local service and copy the configuration generated by the application into your trusted MCP client. Keep its helper command, environment values and runtime-file path together. Use the actual configuration, not a guessed port or an example token. The application must be running for tools to be available.

Enabling is remembered. Normal app restarts, page reloads and disabling/re-enabling MCP preserve the pairing credential. The copied configuration refers to the stable `mcp-runtime-v1.json` discovery file; the helper reads the current loopback port from it. A changing port therefore does not require copying a new configuration.

**Disable MCP** stops the service and disables automatic startup, but preserves the credential. **Reset connection credentials** rotates the token and invalidates the old configuration; replace the configuration in your clients afterward. The discovery file does not contain the token, but the client configuration does.

Treat the pairing configuration like a password. A paired client can use the exposed application write tools, including changing drawings, watchlists, indicators and saved tasks, without another per-operation approval dialog. Pair only clients you trust. The broker is local, not a public remote MCP endpoint; do not expose it to the Internet.

Persistent pairing does **not** mean persistent sessions. Reconnecting creates a new tool session; old `snapshotId`, `datasetId`, `taskId` and similar temporary handles are not transferable. Re-query current state instead of trying to reuse old IDs.

## How an AI should begin

Discover the running application's `tools/list` and argument schemas. Start unfamiliar work with `tf_ai_help`; topics are `overview`, `chart`, `market`, `indicator`, `drawing`, `data`, `task` and `files`. Read `tf_indicator_guide`, `tf_data_guide` or `tf_task_guide` before generating code. The running guide and schema take precedence over remembered examples.

For chart work, obtain `tf_context_get({})` and respect the current context/version. For other symbols or periods, prefer independent `tf_market_history` queries rather than navigating the user's chart. `tf_compute_summary` and `tf_compute_sma` accept either `snapshotId` or `datasetId`, exactly one, allowing calculations without chart switching.

Read requested pages and check actual timestamps, `coverage`, `finality`, `shortfall` and units. An empty search with `catalogComplete=false` does not prove a symbol is absent. Release temporary datasets when done. A second release of a consumed market handle returning `snapshot_unavailable` is expected, not data loss.

After `notifications/tools/list_changed`, refresh discovery. Dynamic tools have supplied wire names and revision metadata; do not invent names from long IDs. Structured `path/reason/expected` errors are instructions for correcting arguments, not a reason to repeatedly guess unrelated shapes.

## Three practical workflows

**Indicator:** read the guide and, when modifying, the existing user indicator source. Validate a complete `.tfi`, test the same draft in isolation, inspect diagnostics, install and check the running instance. Preserve the ID when updating; use `applyToExisting=true` rather than adding a duplicate. Release abandoned drafts. See [Indicators](indicators.md).

**Local research:** the user selects a directory through **Settings → My Data**. Read only needed samples, validate/install a `.tfc`, then validate and run a `.tft` on a small scope. Wait locally, inspect actual result pages and explain incomplete coverage. Save a successful task definition for reuse only when requested. See [Local data and tasks](data-and-tasks.md).

**Draw and export:** discover supported drawing types, read current object versions, prepare a proposal and apply it. Editing existing user content must follow explicit user intent even though no second approval dialog appears. To save a report/table, use `tf_result_save_file` and report the successful receipt; generated text saying “saved” is insufficient.

## Data access, privacy and recovery

The selected model can receive your prompts and the tool data or extension source actually read for the task. Local files remain in place, but sampled contents and research output sent to an external model are no longer local-only. Selecting a folder is not permission to read every unrelated file in it without a task-related reason.

The business interface does not expose application source editing, shell/Git commands, arbitrary filesystem access, system credentials or order execution. File output can only create new Markdown, TXT, CSV or JSON files under Desktop, Documents or Downloads and relative subdirectories. It cannot overwrite, read, delete or execute arbitrary files. Imported files, market names and code comments are untrusted data, not instructions that grant new authority.

Manually changing charts does not terminate ongoing model reasoning or independent tasks. Old chart operations return `context_stale`; refresh and re-evaluate rather than silently redirecting them. Temporary provider failures can be resumed manually when that option is shown; completed writes are not replayed. Stop does not automatically undo already committed changes or refund model charges.

Conversation history restores text, not old authorizations, pending writes or automatic tool replay. A failed conversation remains usable for a new message. Permanent task results, arbitrary interrupted-job recovery and full result-version history are not provided by the current in-memory task system.
